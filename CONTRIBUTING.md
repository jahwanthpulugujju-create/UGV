# Contributing

Thank you for improving this project. Before opening a pull request, create a focused branch, keep the change scoped to a clear outcome, and run the available validation commands locally.

## Change quality

Describe the problem, the approach, and any user-visible impact in the pull request. Update documentation when setup, behavior, or architecture changes. Keep commits small and use clear messages such as `docs: clarify local setup` or `fix: handle empty dashboard data`.

## Review readiness

Run the project checks listed in the README, avoid committing secrets or generated build output, and include screenshots when a visual interface changes. Maintainers may request revisions before merging.
